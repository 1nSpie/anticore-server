# Фотографии из админки

Разделы клиента: `/admin/blog` и `/admin/works` (ссылки в меню).
Блог: загрузка обложки, создание/редактирование статьи, черновики.
Работы: создание/редактирование, фото до/после, галерея до 20 фото, порядок, подписи, услуги и публикация.

Файл отправляется через авторизованный `POST /api/admin/media/blog` или `/api/admin/media/works` (multipart, поле `file`). Сервер проверяет роль `admin`, размер до 10 МиБ, декодирует JPEG/PNG/WebP до 40 мегапикселей, применяет ориентацию и уменьшает до 2400×2400 без увеличения. Сохраняет WebP без EXIF с уникальным именем в `image/blog/` или `image/works/`. Ответ `{key: "blog/<uuid>.webp"}` записывается в существующее поле БД. Миграции не нужны.

## Выкладка через PM2

1. На сервере дополнить `.env` значениями из `.env.media.example`. Реальные ключи вводить только на сервере. У сервисного пользователя Selectel должно быть право загрузки объектов в нужный бакет. Публичное чтение уже используется сайтом.
2. Проверить Node.js: новые зависимости требуют Node.js не ниже 20.9.
3. В конфигурации nginx для API разрешить `client_max_body_size 11m;` и `proxy_read_timeout 120s;`. Проверить `nginx -t`, затем reload. Не дублировать существующий location — добавить настройки в действующий блок.
4. Сначала обновить **бэкенд**: `npm ci`, `npm run build`, перезапустить его процесс PM2. Для ключей, передаваемых через окружение PM2, нужен `--update-env`; `.env` читается приложением при старте.
5. Затем обновить клиент: `npm ci`, `npm run build`, перезапустить клиент. `NEXT_PUBLIC_S3_URL` остаётся прежним. Права S3/секреты браузеру не нужны; отдельная настройка CORS бакета не нужна, поскольку загрузка идёт с сервера.
6. Проверить в админке сохранение черновика, повторное открытие, загрузку и замену обложки, создание работы с фото до/после и галереей, изменение порядка, публикацию и отображение на сайте.

Если сертификат S3 требует системного доверенного центра, настроить `NODE_EXTRA_CA_CERTS=/etc/ssl/certs/ca-certificates.crt` до запуска Node/PM2. Проверку TLS не отключать. При незаданных ключах остальной сайт работает, загрузка возвращает понятную ошибку 503.

## Жизненный цикл файлов

Фото загружается до сохранения записи. Отмена формы, удаление записи или замена фото **не удаляют** объект из S3: он может использоваться другой записью. Неиспользуемые загрузки остаются в бакете; автоматическая сборка таких файлов в эту версию не входит. Старые пути в записях продолжают работать.

Правка SEC-1 в `admin-auth.service.ts` остаётся отдельной: для контента используется дополнительная проверка роли, совместимая со старыми админскими токенами.

## Проверки

`npm test -- --runInBand src/media/media.service.spec.ts src/media/media.controller.spec.ts src/works/works.service.spec.ts`

Тесты подменяют S3, не используют реальные ключи и не пишут в рабочий бакет. Реальная загрузка проверяется после настройки серверного окружения.
